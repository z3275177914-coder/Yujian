# 玉鉴图片格式与媒体支持说明

文档状态：当前实现说明

适用版本：`0.4.7` 及之后遵循同一格式边界的版本

更新日期：2026-09-03

本文把“文件可被目录扫描识别”“系统能否解码预览”“是否播放动画”和“是否能从编辑器导出”分开说明。玉鉴优先使用 macOS ImageIO、Uniform Type Identifiers、Core Image 和 AVFoundation；某一格式最终能否解码，还取决于当前 macOS 的系统编解码器和文件本身是否完整。

## 快速结论

- 普通静态图片浏览和高倍率查看以 ImageIO 为基础，并对大图使用降采样、代理图和受限瓦片/内存缓存。
- GIF 和多帧 WebP 会进入按需动画帧会话；帧按需解码，使用小窗口预取和字节预算，不会默认把全部帧一次性展开到内存。
- Apple Live Photo、Android Motion Photo、Samsung Motion Photo 和旧 Google MicroVideo 不是普通“第三种图片格式”，而是静态图像与视频组件的关系/容器；玉鉴只在关系或容器证据有效时识别并播放。
- 编辑和批量转换的输出格式是 JPEG、PNG、HEIC、TIFF。导出服务读取源文件第 0 帧，因此导出 GIF/WebP 或动态照片时输出的是静态图片，不保留动画视频组件。
- PSD、RAW、SVG 和 AVIF 以系统可提供的预览/栅格解码为边界；当前不是图层编辑器、完整 RAW 开发器或 SVG 矢量编辑器。

## 目录扫描和打开识别

当前代码显式识别以下扩展名（大小写不敏感）：

```text
jpg jpeg jpe jfif
png
heic heif
webp
gif
tif tiff
bmp
avif
svg
psd
dng cr2 cr3 nef arw orf rw2
```

此外，文件类型若能由 macOS `UTType` 判定为 `public.image` 的子类型，也可能被识别。目录扫描只处理当前文件夹的普通文件，不递归进入子文件夹，并跳过隐藏文件。文件扩展名被识别不等于文件内容一定有效；如果 ImageIO 无法创建图像源或解码器不可用，玉鉴会将其视为无法读取的图片，而不会把它当作可用预览。

## 静态格式

| 格式/扩展名 | 浏览/预览 | 当前特殊行为 | 编辑与导出 |
| --- | --- | --- | --- |
| JPEG / JPG / JPE / JFIF | 支持 | 读取 EXIF 方向；带有效容器标记时可作为 Android/Samsung Motion Photo 静态部分 | 可导出 JPEG、PNG、HEIC、TIFF |
| PNG | 支持 | 支持透明通道（取决于文件内容和系统解码） | 可导出 JPEG、PNG、HEIC、TIFF |
| HEIC / HEIF | 支持（取决于系统解码能力） | 可作为 Apple/Android 动态照片静态部分参与检测 | 可导出 JPEG、PNG、HEIC、TIFF |
| TIFF / TIF | 支持（取决于系统解码能力） | 元数据读取依赖 ImageIO 提供的字段 | 可导出 JPEG、PNG、HEIC、TIFF |
| BMP | 支持基础预览 | 不保留 BMP 特有编辑语义 | 可导出为 JPEG、PNG、HEIC、TIFF |
| AVIF | 尝试系统预览 | 不是项目自带外部解码器；系统不支持时无法读取 | 不直接导出 AVIF；可在成功预览后导出其他输出格式 |
| PSD | 以系统可提供的合成预览为准 | 不读取/编辑 Photoshop 图层；不是完整 PSD 编辑器 | 输出为静态 JPEG、PNG、HEIC、TIFF |
| RAW（DNG / CR2 / CR3 / NEF / ARW / ORF / RW2） | 以 ImageIO 可提供的预览为准 | 当前不提供完整 RAW 调整、相机配置或非破坏 RAW 开发 | 输出使用系统成功解码的静态预览 |
| SVG | 尝试系统栅格预览 | 当前不是矢量编辑器；系统无 ImageIO 图像源时无法显示 | 成功栅格化后可输出静态格式 |

“支持”表示项目路径已覆盖，不表示所有相机型号、压缩参数、损坏文件或所有 macOS 小版本都能成功解码。发布前建议用目标 macOS 和真实样本完成清单中的人工检查。

## 动画格式

### GIF

扩展名为 GIF 且 ImageIO 报告多帧时，玉鉴使用动画会话按需读取当前帧和邻近帧。播放按帧时间推进，切换图片或关闭会话后会取消旧任务并释放帧缓存。缩放和平移使用当前帧的既有表示，避免在每个交互事件中重新创建动画图层。

GIF 导出不保留动画。选择 JPEG、PNG、HEIC 或 TIFF 导出时，导出服务从源文件的第 0 帧生成静态结果；如需保留动画，应保留原 GIF 文件。

### WebP

静态 WebP 可按系统 ImageIO 能力预览；多帧 WebP 会沿用 GIF 的动画会话和按需帧策略。当前不提供 WebP 导出，导出会生成静态 JPEG、PNG、HEIC 或 TIFF。

APNG、动画 TIFF 等其他多帧格式没有独立的动画路径保证；即使系统能够预览，也按静态图片路径处理，具体行为取决于 ImageIO 返回的图像源。

## 动态照片

动态照片由一个静态图像条目和可选的视频组件组成。目录扫描只把静态图像放入图片列表，MOV 不会作为普通图片单独列出。

| 类型 | 文件形态 | 识别条件 | 播放行为 |
| --- | --- | --- | --- |
| Apple Live Photo | JPEG/HEIC + 外部 MOV | 优先匹配 Apple 内容标识；标识缺失时只允许同名 MOV 作为低置信度回退，并要求可播放 | 单击静态图像后播放外部 MOV |
| Android Motion Photo | JPG/JPEG/JPE/JFIF/HEIC/HEIF，视频追加在同一文件中 | 读取 XMP 容器信息、偏移/长度并验证 MP4 `ftyp`；读取按范围进行 | 单击静态图像后从受限范围提取并播放 |
| Samsung Motion Photo | 通常为 JPEG/HEIC 容器或带尾部视频的 JPG | 必须先发现 Samsung Motion Photo 标记，再验证视频范围和 MP4 签名 | 单击静态图像后播放嵌入视频 |
| 旧 Google MicroVideo | JPG/JPEG 等静态部分 + 旧 MicroVideo XMP | 使用独立的旧字段解析并验证嵌入 MP4 | 单击静态图像后播放嵌入视频 |

普通 JPG 不包含有效动态照片标记、有效视频范围和 MP4 签名时，会保持为普通静态图片。检测器只读取有界的 XMP/文件范围，不把大图和尾部视频一次性作为一个内存缓冲区载入；检测失败也不会阻止静态图像显示。

导出动态照片时，当前导出接口以静态图像第 0 帧为源，不会把外部 MOV 或嵌入 MP4 复制到新文件，也不会承诺保留 Live Photo/Motion Photo 关系。若要保留动态能力，应保留原始照片及其配套视频。

## 编辑、导出和 AI 输入的格式边界

### 用户导出

当前可选输出：

| 输出 | 特性 | 可选项 |
| --- | --- | --- |
| JPEG（`.jpg`） | 有损、兼容性高 | 质量、尺寸、保持比例、元数据策略 |
| PNG（`.png`） | 无损，适合透明图 | 尺寸、保持比例、元数据策略 |
| HEIC（`.heic`） | 高效压缩，依赖系统编码器 | 质量、尺寸、保持比例、元数据策略 |
| TIFF（`.tiff`） | 无损，适合继续编辑或归档 | 尺寸、保持比例、元数据策略 |

“保留元数据”会尽可能传递 ImageIO 能识别的元数据；“剥离 GPS 位置”只针对 GPS 字段，不等同于删除所有隐私信息。JPEG/HEIC 的质量设置会被限制在安全范围内。输出会先写临时文件，成功后再原子替换目标文件。

### AI 输入

云端 AI 分析请求在本机转成最长边不超过 2048 像素的 JPEG；OpenAI 图片编辑在本机生成最长边不超过 2048 像素的 PNG。用户把输入来源设为编辑结果，或选择当前选区时，会先在本机应用对应的调整/裁剪，再进入上述编码流程。AI 输入临时文件在请求结束后清理，具体网络保留由 Provider 决定；隐私边界见 [`PRIVACY_NOTICE.md`](PRIVACY_NOTICE.md)。

## 元数据和方向

玉鉴读取文件名、文件夹、文件大小、像素尺寸、格式、色彩模型、色彩配置文件、DPI、创建/修改时间，以及 ImageIO 可提供的 EXIF、TIFF、GPS、IPTC 和高级类型信息。JPEG 等格式的 EXIF 方向会参与显示尺寸、解码和导出归一化，避免“信息尺寸”和实际显示方向不一致。

缩略图界面显示文件名和尺寸；更完整的格式、EXIF、GPS、色彩和高级字段位于检查器的信息栏。本说明不承诺能读取每一种厂商私有 MakerNote 字段，也不承诺修改原图中的元数据。

## 已知限制与排查

1. 文件扩展名正确但无法预览时，先确认文件内容没有损坏，并使用目标 macOS 的“预览”验证系统是否提供对应编解码器。
2. 大图、长 GIF、RAW 和动态照片的显示质量/速度受设备内存、GPU、系统解码器和原文件参数影响；自动测试不能替代真实设备回放。
3. GIF/WebP 和动态照片导出为静态格式是当前明确行为，不是播放失败。
4. MOV/MP4 不是独立图片格式；它们只有在动态照片关系或嵌入容器证据有效时参与播放。
5. 公开发布前应在目标 macOS 上用普通 JPG、Android Motion Photo、Apple Live Photo、大图、GIF、WebP、RAW 和导出副本进行实际验证。

本说明只描述当前代码路径，不扩大 macOS 原生解码器或未来格式计划的承诺。任何新增格式都应同时补充目录识别、预览/动画/导出边界、隐私影响和回归样本。
